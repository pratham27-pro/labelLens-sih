# Integrate SAM2 label-mask pipeline behind a single on/off flag

## What exists today (confirmed)
- `server/routers/stateless_video.py` → `POST /api/v1/video/unwrap` (already registered in `main.py`): accepts a video **or** image, returns `frames[]` of base64 masked/rectified 2D label images via `UniversalLabelExtractor` (SAM2).
- Node `scanController.js` has `handleVideoScan`/`processVideoScan` wired to `POST /api/v1/video/frames`, but **broken**: `unwrapVideo` is never imported → every video scan ends `FAILED` (ReferenceError).
- Frontend already sends videos (`api.uploadVideo` → `/api/v1/video/frames`, field `file`) and renders `face_images` results + polls PROCESSING scans automatically. **No frontend changes needed.**
- Blocker: SAM2 checkpoint `server/checkpoints/sam2.1_hiera_large.pt` is **missing on disk**.

## Flag semantics (one param, env or terminal)
New `ENABLE_MASK_SCAN` in `node-server` (default **off**), plus CLI override:
- Terminal: `npm start -- --mask-scan` (on) or `--no-mask-scan` (off, wins over env)
- Env: `ENABLE_MASK_SCAN=true|false` in `node-server/.env`

| | Flag OFF (default) | Flag ON |
|---|---|---|
| Video upload | Rejected: `503 "Video scanning is disabled…"` | New masked pipeline |
| Image scan (single + batch) | Existing pipeline, untouched | Also routed through the masker first |

## Node changes (`node-server`)

**1. `src/utils/scanFlags.js` (new)** — `isMaskScanEnabled()`: reads `process.argv` first (`--mask-scan` / `--no-mask-scan`), then `ENABLE_MASK_SCAN` env (`true|1|on|yes`), default false. Exported and imported where needed.

**2. `src/services/fastapiService.js`** — `unwrapVideo` (line ~150): derive the multipart mime from the filename via the existing `getMimeType()` instead of hard-coded `video/mp4` (unwrap also accepts images). Reuse existing `FASTAPI_VIDEO_TIMEOUT_MS` (180s default).

**3. `src/controllers/scanController.js`**
- Add `unwrapVideo` to the fastapiService import (fixes the live ReferenceError).
- New shared `processMaskedScan({ inspectionId, inputs: [{buffer, filename}], source, category, log })`:
  1. For each input, call `unwrapVideo(buffer, filename)` → masked faces. **Resilience:** if the masker returns nothing for an image input (422/no faces), fall back to OCR-ing the original image directly so the scan still completes.
  2. Per masked face: upload PNG to Cloudinary (`uploadBuffer`) → `runOcr()` → `evaluateOcrCompliance(ocr, category)` → `extractAnnotatedImage` → `hostAnnotatedImage`.
  3. Aggregate exactly like `processPhotoBatch`: dedup declarations by id/field_name, average compliance score, COMPLIANT only if all faces PASS, build `face_images[]` (`face_index`, `filename`, `image_url`, `annotated_image_path`, `compliance_score`, `overall_result`, `extracted_declarations`, `violations`), violations titled `Face N: …`, `violation.createMany`.
  4. `prisma.inspection.update`: `rawOcrOutput = { source: "video-masked"|"image-masked", filename(s), face_count, face_images }`, `extractedDeclarations`, `complianceScore`, status. On error → status `FAILED` with the message (existing pattern). Keeping this as a standalone function (not merged into `processPhotoBatch`) keeps the new path isolated — easy to test and to delete/merge later.
- `handlePhotoScan` / `handlePhotoBatch`: when flag ON, create the PROCESSING inspection as today but fire `processMaskedScan` instead of `processPhotoScan`/`processPhotoBatch` (category passes through). When OFF: unchanged.
- `handleVideoScan`: when flag ON, same 202 + PROCESSING contract, firing `processMaskedScan` with `source: "video"`. When OFF: `503 { error: "Video scanning is disabled", message: "Set ENABLE_MASK_SCAN=true (or --mask-scan) to enable it." }`.
- Leave `processVideoScanLegacy` dead code untouched.

**4. `.env.example`** — add `ENABLE_MASK_SCAN=false` with a comment describing both toggle methods and the FastAPI checkpoint prerequisite.

## Python changes (`server`) — small, test-enabling only
- `routers/stateless_video.py`: fix `content_type` `"image/jpeg"` → `"image/png"` (files are PNG); before processing, if the SAM2 checkpoint is missing return a clear `503` ("run `python scripts/download_checkpoint.py`") instead of a raw 500.
- `scripts/download_checkpoint.py` (new, stdlib `urllib` only): downloads `sam2.1_hiera_large.pt` from the official Facebook CDN into `server/checkpoints/`, skip-if-exists, prints progress.
- No new pip dependencies; router stays registered unconditionally (needed for direct testing).

## Test script
`node-server/test/video_mask_check.js` (new): `node test/video_mask_check.js <file> [--direct]`
- Default: uploads to Node `POST /api/v1/video/frames`, polls `GET /api/v1/uploads/:id` every 2s until terminal status, prints the aggregated result (faces, score, violations).
- `--direct`: posts straight to FastAPI `POST /api/v1/video/unwrap` to isolate which layer fails (Node vs Python vs model).
Uses global `fetch`, no new deps.

## Verification
1. `python -m compileall server` (syntax).
2. `python scripts/download_checkpoint.py`; start FastAPI; `--direct` unwrap test on a sample image and video.
3. `cd node-server && npm test` (flag OFF default → existing photo suite must still pass).
4. Start Node with `--mask-scan`; run `video_mask_check.js` on a sample **image** and **video**; confirm inspection renders faces via `GET /uploads/:id` (`face_images` shape).
5. Start Node without the flag; confirm video upload → 503 and image scans behave exactly as today.
6. `cd web && npm run build` (sanity; no code changed).

## Notes
- First unwrap request loads SAM2 Large (~GBs) and can be slow on CPU — raise `FASTAPI_VIDEO_TIMEOUT_MS` if the first scan times out; later requests are warm.
- Video uploads carry no `category`, so compliance eval uses `"general"` (same as today).
- The unwrap call from the image path intentionally uses the video timeout (SAM2 is slower than OCR).
